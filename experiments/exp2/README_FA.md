# بسته آزمایش دوم (Exp2)

این بسته برای مرحله بعدی آزمایش Generator تهیه شده است. فایل‌های Exp1 را جایگزین نمی‌کند و به `agent.py`، `executor.py` یا Prompt فعلی دست نمی‌زند.

## هدف Exp2

بررسی این فرضیه که مدل زبانی می‌تواند با توجه به مأموریت، الگوریتم یا تابع هزینه واقعاً متفاوتی تولید کند؛ نه اینکه صرفاً نسخه‌ای از A* را برای تمام مأموریت‌ها بازتولید کند.

چهار مأموریت و تعریف عملیاتی آنها:

| مأموریت | هدف اصلی | معیار مستقل |
|---|---|---|
| Efficiency | کمینه‌سازی طول هندسی مسیر | نسبت طول مسیر به کوتاه‌ترین مسیر شبکه‌ای |
| Safety | بیشینه‌سازی حداقل فاصله از موانع | حداقل Clearance مسیر؛ هدف مطلوب ۲ سلول |
| Smoothness | کمینه‌سازی مجموع زاویه چرخش | مجموع زاویه‌های تغییر جهت بر حسب رادیان |
| Multi | توازن طول و فاصله از مانع | مجموع هزینه یال تعریف‌شده در Prompt |

## فایل‌ها

- `mission_prompts.py`: System Prompt مشترک و چهار Prompt مأموریت‌محور.
- `mission_validation.py`: اعتبارسنج مستقل مسیر و معیارهای هر مأموریت؛ مستقل از `evaluate_path()` پروژه.
- `tests/test_mission_validation.py`: آزمون‌های واحد برای اعتبارسنج و Promptها.
- `EXP2_PROTOCOL_FA.md`: پروتکل پیشنهادی، متغیرها و روش اجرای آزمایش.

## اجرای آزمون‌ها در ویندوز

از ریشه مخزن:

```powershell
python -m pytest experiments/exp2/tests -q
```

در صورت نصب نبودن pytest:

```powershell
pip install pytest numpy
```

## نکته سازگاری حرکت

اعتبارسنج Exp2 فعلاً همان قرارداد حرکت فعلی مخزن را حفظ می‌کند: حرکت ۸جهته، هزینه هندسی ۱ و √۲، و مجاز بودن حرکت قطری حتی در گوشه دو مانع. تعداد حرکت‌های قطریِ گوشه‌بُر جداگانه گزارش می‌شود، اما به‌تنهایی مسیر را نامعتبر نمی‌کند. اگر تصمیم بگیریم گوشه‌بُری ممنوع باشد، باید همین قانون را هم‌زمان در Generator، تمام Baselineها و اعتبارسنج اعمال کنیم؛ نباید فقط Generator با قانون سخت‌گیرانه‌تری سنجیده شود.

## نکته مهم

این بسته هنوز Runner اصلی Exp2 را به اسکریپت `run_generator_experiment.py` متصل نمی‌کند. دلیلش حفظ اجرای موفق Exp1 و پرهیز از تغییر هم‌زمان چند مؤلفه است. ابتدا Promptها و Validator را با آزمون‌های واحد بررسی می‌کنیم؛ سپس آنها را در یک Runner جداگانه Exp2 ادغام می‌کنیم.
